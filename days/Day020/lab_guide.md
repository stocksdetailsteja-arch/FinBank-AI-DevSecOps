# 🧪 Enterprise Vulnerability & Compliance Governance Lab

> [!NOTE]
> Day020 uses read-only aggregate metadata and synthetic findings. It does not install a scanner, run intrusive probes, publish real vulnerabilities, modify controls, or claim compliance certification.

## Why This Matters

Vulnerability discovery is only the start. Enterprise governance validates applicability, combines technical and banking context, assigns ownership, authorizes treatment, proves service safety, rescans, and retains closure evidence.

## Production and Banking Lens

Every decision protects payment availability, authentication, fraud controls, queues, databases, ledgers, reconciliation, audit continuity, and recovery objectives.

## Phase 1: Safety
Verify the FinBank root, origin, Day020 branch, and ShopSphere isolation.

## Phase 2: Baseline
Collect OS, kernel, package count, running-service count, listening-socket count, AppArmor state, and reboot marker.

## Phase 3: Synthetic Findings
Review severity, exposure, exploit maturity, asset tier, controls, and treatment fields.

## Phase 4: Priority and Compliance
Generate the effective-risk review and compliance-evidence review.

## Phase 5: Decision and Failure
Generate the remediation record, then invoke the analyzer with a missing file and verify exit code `66`.

## Phase 6: Final Gates
Run the validator, inspect evidence, capture ten screenshots, and run Git whitespace checks.
